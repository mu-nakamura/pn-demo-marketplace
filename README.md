# pn-demo-marketplace

ペルソノーツの考え方（判断と理由を記録に残し、次回は記録を前提に再開し、別の役割が記録から確かめる）を、Treasure AI Studio で見せるためのデモ用スキル集です。Studio のプラグインマーケットプレイス形式（`.claude-plugin/marketplace.json`）で作ってあります。

- 題材は架空（北精機・経営企画の「来期の重点投資テーマ」）。実在の会社名・数値は含みません。
- ペルソノーツ本体の定義文は含みません。スキルの本文はこのデモ用に書いたものです。
- 記録は OKF（Open Knowledge Format）v0.2 に従う Markdown です。

## スキル（プラグイン `pn-demo`）

| 呼び出し | 役割 | 使う場面 |
|---|---|---|
| `/pn-demo:setup` | 準備 | 作業フォルダに `inputs/`・`drafts/` の種ファイルを作る（既存は上書きしない） |
| `/pn-demo:conductor` | 指揮役 | 目的の確認、判断の整理、記録の提案と保存、「前回の続き」での再開 |
| `/pn-demo:planner` | 企画役 | 記録を前提にした検討資料の下書き（`drafts/`） |
| `/pn-demo:verifier` | 検証役 | 成果物を記録だけを根拠に突き合わせる（読むだけ） |
| `/pn-demo:check` | 点検 | `records/` の OKF 適合を確認（リハーサル用） |
| `/pn-demo:reset` | 初期化 | `records/`・`drafts/` を `archive/` に退避して最初の状態に戻す（削除しない） |

デモの流れは、台本（`デモ台本案_v0.5_…md`）を参照してください。

## 設計の方針

- **マーケットプレイスの形式**：Treasure の公式マーケットプレイス（td-skills）と同じ書き方。1リポジトリ＝1マーケットプレイス＝1プラグイン。`marketplace.json` の `skills` にスキルのパスを列挙する。
- **スキルだけを配る**：Studio のドキュメントでは、プラグインは「スキルをまとめたもの」。フォルダの指示（CLAUDE.md）は運べないので、規則は各スキルの本文に入れてある。
- **補助ファイルに頼らない**：種ファイルや点検スクリプトは `SKILL.md` に埋め込んである（プラグインのスキルフォルダ内のファイルを Studio が読めるか未確認のため）。`tools/` のスクリプトは開発用の控えで、配布物の動作には使わない。
- **記録は人の同意があってから**：提案 → 同意 → 保存。既存の記録の本文は書き換えず、追記か新規。
- **検証役は読むだけ**：別チャットで、記録だけを根拠に確認する。
- **削除しない**：やり直しは退避（`/pn-demo:reset`）。

## GitHub への登録と Studio での使い方（手動）

1. GitHub に**公開**リポジトリを作り、このフォルダの中身をルートに push する。`.claude-plugin/marketplace.json` がルートにあること。
2. Studio（Web / Desktop）の **設定 → マーケットプレイス → マーケットプレイスを登録** で、`https://github.com/<owner>/<repo>.git` を入力する（`.git` で終わる HTTPS の URL）。
3. 登録後、`pn-demo`（`pn-demo@pn-demo-market`）をオンにする。
4. **新しいチャット**を開く（有効化は新しいセッションから反映される）。
5. 作業フォルダ（私的なもの。共有作業フォルダは使わない）で `/pn-demo:setup` を実行し、デモを始める。

注意：
- 公開リポジトリの中身はインターネット上の誰にでも見える。公開前に、`marketplace.json` の `owner`、ライセンス（このフォルダには付けていない）、内容の確認を。
- 組織のネットワークポリシーで `github.com`（ホスト単体）が許可されている必要がある。
- アカウントポリシーが「管理者のみ」だと、ユーザーはマーケットプレイスを登録できない。

## 開発・リハーサル中の反映について

マーケットプレイスの更新はセッション開始時に確認され、**マーケットプレイスごとに最大1日1回**。修正がすぐ反映されないことがある。

- リハーサル中に素早く直したいとき：`skills/` の各フォルダを、作業フォルダの `.claude/skills/` にコピーして試す（この場合の呼び出しは `/conductor` のようにプレフィックスなし）。
- アカウント内だけで試したいとき：Studio の「カスタムスキルの共有」（Develop タブ → Share → Push update。GitHub 不要）。

## push 前の確認

```
python3 tools/validate_marketplace.py
```

`marketplace.json` の JSON、名前の形式（小文字・数字・ハイフン）、各 `SKILL.md` の存在と frontmatter、1MB 超のファイルが無いことを確認する。
